vProgsとSTARKを活用し、国家規模の選挙に「表示の真正性」と「スケーラビリティ」をもたらす次世代投票プロトコル

---

## 🌟 プロジェクト概要

BitBallotは、**Kaspa**などのBlockDAGアーキテクチャをL1（データ可用性・順序付け層）として活用する投票システムです。 
既存の電子投票が抱える「端末改ざんによる意図のすり替え」や「集計中の中間情報漏洩」を暗号技術で解決しつつ、監視された投票所という現実的な制度的運用を前提としています。

## 🚀 クイックスタート (Quick Start)

プロジェクトの全体像をローカルで確認するための手順です。

```bash
# クライアント(WASM)のビルド準備
cd client-wasm

# Webアプリの起動
cd ../web-app

```

## ✨ 主要機能 (Core Features)

### 🔒 Atomic Display Integrity (ADI)
有権者の意図、画面表示、および記録される暗号文を**単一のアトミックな承認イベント**として結合します。  
これにより、端末が改ざんされていても「画面表示と異なる候補者」を裏で承認させる攻撃を不可能にします。

### 🎭 集約されたダミー投票 (Aggregated Batching)
1つの真の投票と複数のダミー投票をローカルで一括処理します。  
これらは単一のSTARK証明として集約され、L1には1つのトランザクションとして提出されるため、外部から真の意図を特定することはできません。
※本実装では「本命1枚 + ダミー9枚 = 合計10枚」のバッチ構成を採用しています。

### 🏁 ターミナル・コンプリート（終端完了型）集計
投票期間中、L1はデータの順序を確定させるだけで、**途中集計は一切行いません**。  
選挙終了後に初めて、ガーディアン（後見人）が閾値復号とゼロ知識証明を用いて最終結果を算出します。

### 🛡️ 最終投票有効（Last-Vote-Valid）セマンティクス
一人の有権者が複数回投票（再投票）することを許容し、常に**「最後に提出された有効な投票」**を最終結果として採用します。  
これにより、買収や脅迫による一時的な投票指示を無効化する余地を与えます。

### 🌐 検閲耐性オートルーティング (Anti-Censorship Routing)
特定のノードによる意図的なトランザクションの破棄（投票の検閲）を防ぐため、候補者・政党ごとに独立した入口ノードを構築できる設計になっています。
システムは有権者が選択した候補者の陣営ノードへ投票データを自動で優先ルーティングし、万が一妨害やサーバーダウンがあった場合は中立ノードへ即座にフォールバックします。この仕組みと「ダミー投票の集約」を組み合わせることで、ノード運用者ですら真の意図を判別できなくなり、あらゆる検閲を無力化します。

## 🏗️ 技術アーキテクチャと将来展望

### 1. 実行に依存しないL1の活用
BitBallotはスマートコントラクトや専用のL2チェーンを必要としません。
- **L1 (Kaspa等)**: 不変のデータ保存と順序付け（Ordering）のみを担当。
- **オフチェーン実行**: 投票ロジックの検証は、各ノードがオフチェーンで行う「検証可能なプログラム（vProg）」形式で実施。

### 2. STARKによる無限のスケーラビリティ
投票端末は、バッチ全体の正当性を証明するSTARKを生成します。
- **並列検証**: L1ノードは投票時に重い証明の検証を行う必要がなく、集計フェーズで並列・一括して検証可能。
- **国家規模への対応**: 1億人の有権者がいても、検証作業は数日以内に汎用サーバー群で完了可能。

### 3. 汎用ハードウェアの採用 (Cost Effectiveness)
高価な専用ハードウェアや信頼実行環境（TEE）を排除し、オフィス用PCなどの安価な汎用ハードウェアで動作するよう設計されています。

## ⚠️ 重要な設計上の前提条件

- **監視下での運用 (Supervised Environment)**: 自宅などでのリモート投票は、物理的な強要や監視を防げないため、明示的に「対象外」とされています。
- **制度的責任の分離**: 暗号技術は「正当性」を保証しますが、「有権者の資格確認」や「強要の防止」は、既存の法的・物理的な制度（投票所や住民登録）が担います。
